# Сайт доставки питьевой воды

Многостраничный сайт для продажи и доставки питьевой воды по Ташкенту: каталог (5, 10 и 20 литров),
страницы товаров, корзина и оформление заказа. Языки: русский (основной) и узбекский (латиница).

Данные компании, товары, условия доставки и тексты задаются в папке `config/`, без правки исходного кода.

## Технологии

Next.js 16 (App Router, Cache Components), React 19, TypeScript, Tailwind CSS 4, next-intl,
Zustand (корзина в localStorage), react-hook-form + zod, Motion, Radix Dialog, Sonner, Vitest.

## Требования

- Node.js 22.12+ или 24 LTS (Next.js требует 20.9+, Vitest 5 — 22.12+; диапазон указан в `engines`)
- npm

## Установка и запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

Сборка и запуск production-версии:

```bash
npm run build
npm start
```

Проверки:

```bash
npm run typecheck    # TypeScript, в том числе файлы config/
npm run lint         # ESLint
npm test             # Vitest: корзина, калькулятор, оформление заказа, API
```

## Структура

```
config/              настройки компании, товаров, доставки и текстов
messages/            переводы интерфейса (ru.json, uz.json)
public/              статические файлы: иконки, логотип, фото товаров
src/app/             страницы, API приёма заказов, sitemap, robots, OG-картинки
src/components/      компоненты интерфейса
src/lib/             каталог, корзина, заказы, форматирование, SEO
src/i18n/            маршрутизация и загрузка переводов
tests/               unit-тесты
```

Русская версия открывается без префикса (`/catalog`), узбекская — с префиксом `/uz` (`/uz/catalog`).

## Настройка

Общее правило: пустая строка `''` или `null` означает «данных нет». Такие кнопки, строки и блоки
на сайте не показываются. Пустой узбекский перевод заменяется русским.

| Что                                                      | Где                                          |
| -------------------------------------------------------- | -------------------------------------------- |
| Название, логотип, телефоны, e-mail, адрес, часы работы  | `config/site.ts`                             |
| Мессенджеры и соцсети                                    | `config/site.ts` → `social`, `otherLinks`    |
| Способ приёма заказов                                    | `config/site.ts` → `orders`                  |
| Товары: цены, наличие, фото, описания, характеристики    | `config/products.ts`                         |
| Условия доставки и оплаты, районы в форме заказа         | `config/delivery.ts`                         |
| Текст «О компании», частые вопросы                       | `config/content.ts`                          |
| Надписи интерфейса                                       | `messages/ru.json`, `messages/uz.json`       |

После правки конфигурации запустите `npm run typecheck`: проверка подскажет, если, например,
цена записана строкой.

### Компания и контакты

В `config/site.ts` замените рабочее название `brand.name` на настоящее и заполните `contacts`.
Первый телефон из `phones` показывается в шапке сайта.

Логотип положите в `public/brand/` (лучше SVG) и укажите путь:

```ts
logo: '/brand/logo.svg',
logoOnDark: '/brand/logo-white.svg', // светлая версия для тёмного подвала, необязательно
```

### Соцсети и мессенджеры

В `social` достаточно имени или ссылки:

```ts
telegram: 'mycompany',          // или '@mycompany', или 'https://t.me/mycompany'
whatsapp: '+998 90 123 45 67',  // номер в любом формате
instagram: 'mycompany',
```

Заполненные сети появляются в мобильном меню, подвале, на странице контактов и в призывах к заказу.

### Товары и цены

```ts
price: 25000,  // цена в сумах, числом
price: null,   // цена неизвестна: «Цена уточняется», итог заказа не считается
```

Цена за литр, суммы в корзине и итог заказа считаются автоматически. Пока хотя бы у одного
товара в корзине нет цены, итоговая сумма не выводится.

Чтобы добавить товар, скопируйте блок товара в `config/products.ts` и поменяйте `id`, `slug`
(латиница, цифры, дефис), название, объём и тексты. Товар появится в каталоге, меню, подвале
и карте сайта и получит страницу `/catalog/<slug>`. `visible: false` скрывает товар,
`inStock: false` отключает покупку.

Фото товаров кладутся в `public/images/products/` и указываются в поле `image`
(например, `'/images/products/water-20l.webp'`). Лучше всего подходят WebP или PNG около
1200×1200 px на прозрачном или белом фоне, в одинаковом ракурсе для всех объёмов. Пока `image`
равно `null`, показывается встроенная SVG-иллюстрация тары.

## Приём заказов

Способ задаётся в `config/site.ts` → `orders.channel`:

- **`'api'`** — заказ уходит на сервер сайта (`POST /api/orders`), а оттуда в Telegram-бота
  и/или CRM. Каналы включаются переменными окружения, см. `.env.example`:
  - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — сообщения в чат менеджеров;
  - `ORDER_WEBHOOK_URL`, `ORDER_WEBHOOK_SECRET` — JSON с заказом в CRM или любую систему.
- **`'whatsapp'` / `'telegram'`** — без сервера: у покупателя открывается мессенджер с готовым
  текстом заказа (контакт берётся из `social`).

Пока выбранный способ не настроен, оформление на сайте недоступно: в корзине и на странице
оформления вместо формы показывается соответствующее сообщение и контакты компании (если они
заполнены), а блок «Как заказать», кнопки «Оформить заказ» и призывы заказать онлайн скрыты.
Корзина при этом сохраняется. Доступность проверяется при каждом запросе, поэтому переменные
окружения можно менять без пересборки. Сообщение об успешном заказе выводится только после
подтверждения сервера.

Сервер заново проверяет поля и берёт названия и цены из каталога. Если товара нет в каталоге,
он скрыт или закончился, позиция повторяется или цена отличается от той, что видел покупатель,
заказ отклоняется с понятным сообщением — состав заказа никогда не меняется молча. Ботов
отсекает скрытое поле-ловушка. Новый канал (например, e-mail) добавляется
в `src/lib/order/channels.ts`.

### Надёжность приёма заказов

- **Повторы.** Браузер отправляет ключ операции (`idempotencyKey`), одинаковый для всех попыток
  отправить один и тот же заказ: повторное нажатие, повтор после таймаута, параллельные запросы.
  Сервер возвращает тот же номер заказа и не отправляет заявку повторно. CRM получает ключ
  в заголовке `Idempotency-Key` — по нему она может отбрасывать дубликаты со своей стороны.
- **Несколько адресатов.** Каждый чат Telegram и webhook учитываются отдельно. Заказ принят,
  если его получил хотя бы один адресат; остальным заявка досылается в фоне, а повтор
  от покупателя досылает её только тем, кто её ещё не получил.
- **Ограничения.** Ключи и статусы хранятся в памяти процесса (24 часа). После перезапуска
  сервера или на другом экземпляре (serverless, несколько реплик) повтор будет доставлен
  заново — с тем же номером и тем же `Idempotency-Key`. Telegram не умеет отбрасывать повторы,
  а если адресат принял заявку, но не успел ответить (таймаут), сервер повторит доставку.
  Поэтому гарантия — «заказ не теряется и не размножается в пределах одного процесса», а не
  «ровно один раз». Для строгой гарантии нужны общее хранилище ключей (например, Redis/Upstash)
  и CRM, поддерживающая `Idempotency-Key`; фоновое досылание без очереди тоже живёт, только пока
  жив процесс.
- **Защита API.** Не больше 10 запросов за 10 минут с одного адреса (проверяется до разбора
  запроса и обращений к Telegram/CRM), тело запроса — до 16 КБ. Лимит хранится в памяти процесса
  и берёт адрес из заголовков `X-Real-IP`/`X-Forwarded-For`, поэтому сайт должен стоять за
  прокси, который их выставляет (Vercel, nginx). Для публичного запуска лимит стоит продублировать
  на уровне хостинга: Vercel Firewall, Cloudflare или `limit_req` в nginx.
- **Webhook** принимается только по `https://` (http — лишь `localhost` для разработки),
  без логина и пароля в адресе; редиректы запрещены. Иначе webhook отключается с ошибкой в логе.

### Данные покупателя в браузере

Корзина хранится в localStorage; если хранилище недоступно или данные повреждены, корзина
работает в памяти страницы. Имя, телефон, район, адрес и ориентир запоминаются только если
покупатель отметил галочку, и только после оформления заказа; сохранённое удаляется снятием
галочки или кнопкой «Удалить сохранённые данные».

## Публикация

- **Vercel**: импортируйте репозиторий и задайте переменные из `.env.example`.
- **Свой сервер**: `npm ci && npm run build && npm start` (порт 3000) за обратным прокси.

Укажите публичный адрес сайта в `config/site.ts` → `url` или в `NEXT_PUBLIC_SITE_URL`. От него
зависят канонические ссылки, карта сайта (`/sitemap.xml`) и превью в мессенджерах. Пока адрес
не задан, сайт закрыт от индексации (`robots.txt` и `noindex`). Корзина и оформление всегда
закрыты от индексации через `noindex`. Объёмы в SEO-описаниях и заголовках («5, 10 и 20 л»)
берутся из каталога и меняются вместе с ассортиментом.

## Перед запуском

- Заменить рабочее название `Suv` на название компании, добавить логотип.
- Указать цены, характеристики, фото товаров, контакты и условия доставки.
- Настроить приём заказов и проверить отправку тестового заказа.
- Проверить с юристом текст политики конфиденциальности (`messages/*.json` → `privacy`)
  и дополнить его реквизитами компании, в том числе с учётом закона Республики Узбекистан
  «О персональных данных».
